# Gemma 4 26B-A4B IT: literature foundation

Research date: 2026-09-07. This note supplies the literature portion of Phase 5. Public `main` files below are mutable reference implementations, not proof of the installed pack's identity. The parent investigation owns the dirty-checkout, pack and prompt-template comparison.

The useful question is which selected weights recur during our actual navigation stream, and whether retaining them saves enough loading time within the memory budget. A model's active parameter count alone does not answer that question.

Proposed trace analysis, not a completed measurement: split saved or future observations into navigation instructions, screenshots, recovery, tool-result prefill and generated thinking/action tokens. For each layer, count selected IDs, adjacent-token overlap, unique IDs in each prefill batch, reuse distance, hit/miss frequency and bytes fetched. Replay cache capacities without changing routing. Pair this with whole-turn latency and screenshot memory peaks. A frequent expert may be useful to retain without having a human-readable task specialization.

Do not infer that the model never encountered accessibility trees. Do not infer that broad vision and function-calling capability proves extensive training for this exact iOS workflow. Action outcomes remain grounded in VisionCapture evidence.

Recommendation: establish input fidelity and successful-action timing, then measure actual expert reuse. The literature supports that measurement plan, but does not yet justify a cache-policy change, Metal patch, larger resident cache or promised token rate.
