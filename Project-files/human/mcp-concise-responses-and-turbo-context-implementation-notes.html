Input to Gemma
The user task, navigation tool, current screen facts, and last action result. Include actual image content when it helps. Proposed short IDs such as a1 must be privately bound to the exact current observation, device, session, selector, selector kind, role, and required execution evidence.
Output from Gemma
One decision, for example {"action":"tap","target":"a1"}. The working-tree tool schema now includes target. These packet examples remain illustrative and have not been verified against a new run. IDs increase within the conversation and are never reused for a later observation. Retired IDs cannot select a new control. Unknown, ambiguous, stale, or mismatched IDs must fail before input delivery. Each catalog example is independent.
Host request
TurboCharge translates that choice into the exact MCP contract, validates the reply, and performs mandated reads without asking Gemma to manage protocol steps. Required device/session identity, grants, selectors, alert digests, and delivery facts remain in the host and consumer wire contract. They need not appear in model text.
Build policy
Owner decision, 7 September 2026: Release = concise only. Debug = detailed. Compile the detailed response formatter only into Debug builds. Keep Debug builds private and distribute only verified Release builds to production. Keep the same public MCP schema in both builds, with no response-detail argument, header, setting, or environment override that can enable detailed output in Release.

A standalone executable built from the frozen pre-edit parser changes JSON-quoted "Hello world" to "Helloworld", because its character reader skips whitespace inside that string path. Operation order
Local generation follows the pinned MLX order: cumulative-probability filtering, candidate-count filtering, then temperature for the draw. The pinned Transformers path applies temperature, candidate-count filtering, then cumulative-probability filtering. Exact-arithmetic examples yield different eligible tokens even at temperature 1. This is a comparability limit, not a demonstrated local defect or a known Google benchmark setting. See the sampling audit.
Randomness
Current app requests do not supply a seed. Saved preferences can override defaults. Repeated UI runs are therefore not a seeded paired experiment, and identical seed numbers across different engines would not ensure the same random draws.
