Proposed tasks done

We already cache requested experts in Metal buffers. slotExpert[3] = 19 means slot 3 contains expert 19. Finding expert 19 currently requires scanning slots. The proposed expertToSlot[19] = 3 supplies the location directly. A value of −1 means no ready copy is indexed.

Both arrays are needed: one finds weights, the other identifies what is replaced. Sorting orders replacement candidates by cache policy. It is unrelated to database queries.

Experts are loaded on demand. Unrequested experts are not read into slots. A 128-slot setting is capacity per layer, not a command to preload every expert. The router can select different experts on later tokens.

Found
Source finding

The planner sorts even when nothing is missing

PreadExpertStreamer.makeExpertCachePlan scans slots for each expert and constructs sorted replacement candidates before handling an all-hit result. Metal selects eight experts per layer across 30 layers. Up to 30,720 slot checks per token at 128 slots is a loop upper bound, not a timing measurement.

Built
Implemented · benefit unverified

The planned fetch already skips one queue hop

ModelExpertIO.fetchRoutedExperts(plan:) directly returns cached buffers when all requested experts are present and measurement capture is disabled. This change was built earlier. Its throughput benefit is not verified. The unplanned overload and measurement-enabled fetch retain their queue paths.

2.2Add an array indexed by expert IDOpen
Why
Locate ordinary cached experts without scanning every slot.
Files
PreadExpertStreamer.swift · stored arrays, initializer, makeExpertCachePlan and executeExpertCachePlan.
Implement
Add expertToSlot as Int32 entries sized from layout.expertsPerLayer, initialized to -1. Keep slotExpert and slotBuffers. Resolve each expert by direct indexing and validate current ownership and reservations. Map to the lowest matching ready slot. Fall back to the existing scan when that copy is reserved. Invalidate or repoint the old expert when reserving a victim. Publish both directions together under cacheLock only after the read batch succeeds. Reinitialize with streamer lifetime.
Preserve
Duplicate requested IDs, duplicate resident copies, failed-batch publication, LFU/LRU ordering and pending prefill buffers. Existing ready hits may be shared; protected buffers may not be overwritten. Keep updates atomic under the current lock. Do not publish unfinished reads.
Visible result
The usual eight-expert request uses eight table lookups. Extra element storage is about 15 KiB over 30 layers, excluding allocation overhead.
Done when
Focused comparisons cover ordinary hits, misses, replacement, duplicates, failed reads and protected prefill slots. Assignments and generated output match. Pending.
