## Design that the next agent must preserve

- Phase 2 separates source content identity from the local root path and rejects mixed packed/source layouts. Actual source registration remains future work. Preserve Gemma v1 and historical packed-v2 fixture paths.
- Task 5.6 moved bounded Safetensors metadata parsing, index parsing and shard membership validation into the shared source module; runtime must not import the repacker. Task 5.7 extracted the full pinned payload verifier into that shared target while retaining the RepackCore adapter. Later registration must use that verifier and preserve the existing full-SHA and trusted-receipt choices. Metadata-only checks are not full payload authentication, and Task 5.7's tiny synthetic tests do not establish authenticity of the original download.
- Read exact BF16 source bytes directly into final Metal shared buffers. Chunk large embeddings and the output head on complete rows. Avoid persistent Float32 copies of large shared weights. FP32 calculation and state are separate from source-weight precision.
- An expert has a gate/up range and a down range, potentially in separate shards. Publish one cache slot only after both reads succeed. Cancellation must wait for outstanding reads, and the GPU must retain both buffers until it finishes.
- For future P22, use the independently parsed, pinned official Transformers reference. It must process all 40 layers in order, loading all 256 supplied BF16 expert slices for only the current layer, calling the official layer and routing math, then releasing those weights before the next layer. Retain required activation/KV/recurrent state and use chunked embeddings, final normalization and a chunked output head to produce full logits. It exits before the candidate runs. This is FP32 math over supplied BF16 values, not a claim of physical shard authenticity or publisher-BF16 bit identity. Task 3.6 ran only one isolated layer, not this 40-layer sequence.
- Validate both raw FP32 logits and the public Float16 output boundary. Freeze tolerances before qualification. Record routing ties and margins rather than hiding mismatches.
- Vision requires a verified adjacent source-backed `.vision.gturbo` metadata companion. Load one vision weight group at a time. Missing or invalid vision support must reject images explicitly.

The metadata estimate is 4.560 GiB for shared text weights plus 3.750 GiB for 16 expert slots per layer, about 8.31 GiB for weight buffers only. State, scratch, images and system use are additional. Actual **source-backed Swift/Metal runtime** fit and speed on the 32 GiB M2 Pro remain unmeasured; the separate one-layer CPU measurement below does not qualify them. The current app retained-state path uses 8 slots, while CLI generation passes its configured count. Do not describe 16 as the current app runner setting. The bundle loader also accepts streaming and cache-policy options without forwarding them through its Qwen branch; the revised plan must make those settings effective.
