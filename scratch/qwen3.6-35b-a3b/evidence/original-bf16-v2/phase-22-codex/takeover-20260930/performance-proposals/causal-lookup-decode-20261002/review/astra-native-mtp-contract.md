Minimal one-draft recurrence, zero-based token indices
Let x_j be target token j and h_j its post-final-norm target hidden row. Let K be the separate MTP KV prefix. Define M(h_j, embedding(x_{j+1}), position=j, K) as one MTP transformer update, returning a hidden used by the shared language head to propose x_{j+2}.
1. After target prompt x_0…x_(P−1), the target samples pending x_P. Populate MTP KV by processing (h_j, x_(j+1), j) for EVERY prompt row j=0…P−1, using pending x_P at the final row. Sample only the final MTP row to obtain draft d_(P+1). Last-row-only initialization is not equivalent.
2. Target verifies [x_P, d_(P+1)] with the exact existing target sampler and its own random/history state. On rejection, only x_P is consumed and correction x_(P+1) remains pending. Append MTP row (h_P, correction, P), then sample its next draft. The unaccepted target hidden row is never part of this MTP history.
3. On acceptance, target consumes both inputs and samples bonus pending x_(P+2). Append TWO MTP rows: (h_P, accepted x_(P+1), P), then (h_(P+1), bonus, P+1). Sample the last row. The first is necessary cache catch-up even though its logits need not be calculated. Thus a successful two-token target cycle still requires two MTP transformer rows, not one.
4. EOS termination needs no next draft. Target pending/consumed rules remain separate from MTP KV positions. Prompt initialization and every catch-up row belong in total proposal cost.

KV rejection and deeper drafts
The implementation calls the first draft pass over the target query shape and reuses position/slot mappings ([303–327](https://github.com/vllm-project/vllm/blob/f700178f90d21f21fea2b495475e83b267290c01/vllm/v1/worker/gpu/spec_decode/autoregressive/speculator.py#L303)). It may retain rejected placeholders for graph shape, but selects the last VALID row before them. Subsequent draft steps [subtract rejected lengths](https://github.com/vllm-project/vllm/blob/f700178f90d21f21fea2b495475e83b267290c01/vllm/v1/worker/gpu/spec_decode/autoregressive/speculator.py#L853). Each additional speculative step [feeds its own prior MTP hidden and drafted token and advances positions](https://github.com/vllm-project/vllm/blob/f700178f90d21f21fea2b495475e83b267290c01/vllm/v1/worker/gpu/spec_decode/autoregressive/speculator.py#L933). Next-cycle target-derived rows overwrite that provisional suffix. Our simpler trimmed implementation should expose only the accepted MTP prefix, overwrite stale suffix slots, and never treat provisional MTP state as target state. The one-draft variant avoids the extra self-fed draft steps entirely.

Remaining boundaries
- This pins vLLM behavior, not an official training specification or numerical oracle for checkpoint 995ad96. Its GPU/precision kernels do not prove our BF16-source/FP32 arithmetic reproduces its draft logits. Target exactness must remain enforced by independent verification regardless of draft accuracy.
- Multimodal embedding replacement and three-axis positions need their own call-path audit. The simple recurrence above is for text. It must not replace actual image features with token embeddings silently.
- The target currently exposes prompt logits, not a retained stream of all post-final-norm hidden rows for MTP initialization. Stream bounded prompt-row chunks to a separate owner rather than assume the last row suffices or retain every long-context row.
- Target sampling and MTP sampling must use distinct state. Copying vLLM's probabilistic rejection sampler would not establish the repository's stronger same-token-sequence requirement.
- Source admissions, cancellation/draining, target prefix settlement and outer rollback lineage remain our own contracts; vLLM is not evidence permitting their removal. Memory headroom and native acceptance/cost remain unmeasured.

Conclusion: the single-draft causal recurrence and mandatory prompt/catch-up work are now specified from a pinned caller. This removes an architectural ambiguity, but does not qualify a native head or change Main's selected recurrent-only recovery experiment.
