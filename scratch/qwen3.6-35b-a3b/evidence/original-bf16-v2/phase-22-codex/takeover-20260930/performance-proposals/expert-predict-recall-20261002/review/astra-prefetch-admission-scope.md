Conditional decision: a quarantine design is technically plausible, but there is no existing paired-reader API that can be called unchanged to read into quarantine and then safely import into real slots. Do not authorize prefetch from this note. First require the CPU-hint gate, then review a narrowly typed reader/import boundary.

Existing protected primitive: Sources/TurboFieldfareOfficialQwenSource/OfficialSourceHandle.swift, preadTensorRange → readPlan (:633) → readTensorRangeCore (:665). TensorRange (:30) is issued only by admitTensor, retains its issuing handle and exact FD/fingerprint/shape/range, and closes that FD on deinit. readPlan rejects foreign tokens, offset/count overflow and tensor/file boundary violations. Each actual syscall retains before/after validation and the final before-return validation, with the existing 8MiB call and 4MiB syscall bounds. Use this API unchanged, never raw pread or caller-provided shard offsets.

Existing paired owner: Sources/TurboFieldfare/Infrastructure/Streaming/PreadExpertStreamer.swift, QwenBF16PairedExpertCache.init (:575), load (:689), validateBoth (:764), read (:776). It admits and shape-checks gate/up and down tokens, computes expert-relative ranges from fixed geometry, and delegates every byte to preadTensorRange. The read helper is private and targets the cache’s Metal buffers. load invalidates real victims before reads and publishes slotExpert after hooks and validateBoth. Calling load on a predicted real plan would change LFU state/eviction and is therefore unsuitable.

Smallest future boundary: a private immutable paired-read owner extracted from those already-admitted ranges, with an explicit 0..<expertCount check and checked pair geometry, can read one expert into exact-sized quarantine destinations through the SAME protected helper. It must retain the source/ranges, not recreate admission from predicted IDs or exposed numeric offsets. One reusable allocation contains up to eight disjoint gate4MiB/down2MiB pairs, 48MiB total for this model. Keep actual LFU16 buffers unchanged and account this allocation in the existing reservation/free-memory guard. No FP32 router cache, full-weight copy or extra persistent expert cache. At the last run’s 30% minimum, allocation feasibility is unproven.

Quarantine lifetime: bind each entry to owner identity, layer, bounded expert ID, generation/position epoch and completed gate+down status. Never expose it to a GPU or mark an actual slot valid. It stays immutable after successful reads until import/discard. At most one next-layer batch is active. Old epochs cannot cross rollback, turn boundaries or reuse of the allocation. Target-layer source tokens and quota remain strongly owned through every dispatched read and its completion.

Demand remains the decision-maker: preserve QwenOfficialSourceRunner.moeStep’s full-source pre-map check. Drain the owned quarantine batch before acquiring/holding a lock its completion needs. Then QwenBF16ExpertMappingCoordinator.performFetch (ModelExpertIO.swift:896) uses the actual Top8 route, existing avoidingSlots and cache.plan exactly once. Only actual misses whose expert/layer/owner/epoch matches a fully successful quarantine pair can be considered. Predicted-but-unused entries do not affect plan, counters, useCount, lastUse or eviction.

Before any import, run fresh validateBoth on those SAME retained tokens and validate the exact destination sizes/reserved slot binding. Invalidate actual victims before copying, as today. Copy both streams from immutable quarantine into the actual assigned missed slot. Run fresh validation again after copy and retain the ORIGINAL serial beforePairPublish hook, cancellation checks and validateBoth immediately before slotExpert publication. Preserve unchanged hit checks, lease pins and runner post-map full-source check before GPU use. A source/binding/identity failure discards quarantine and invalidates affected victims, without publishing either stream. Do not silently hide an observed authenticity failure by retrying ordinary reads. Missing prediction/unfinished benign entry may use the ordinary demand path only after owned work has drained and errors are resolved.

This design reuses bytes, not the earlier validation result: held/named source identities, marker and bindings are checked afresh before copy and publication. File changes before/during prefetch are covered by the protected reader, and changes after it by demand/import/publication checks. Predicted IDs never bypass TensorRange admission. It still changes when optional reads occur relative to the next layer’s full scan, so inter-entry/mutation-observation equivalence and treatment of speculative errors require review rather than an assertion of unchanged temporal behavior.

Cancellation: the existing load canceled closure is checked between read batches and before publication, while its launched streams are always joined. A new owner must preserve that drain rule, stop launching on its linked cancellation flag, complete each in-flight protected read/close path, and join before releasing quota, tokens, buffers or rollback state. Do not assume Task.checkCancellation inside Dispatch inherits the parent. Do not close token FDs to interrupt reads. No state/IO lock may be held while waiting on a worker that needs it. If hooks are arbitrary, retain the ordinary demand path unless genuine no-hook provenance is established; requiresSeparateGPUStages is not that proof.

Decisive prerequisite: the code has neither a mutation-free quarantined paired-read owner nor an import operation that preserves invalidation, fresh validation and publication. Existing cache.load cannot stand in for them. CPU recall success would justify reviewing that narrow boundary and its memory/cancellation budget, not launching prefetch immediately.
