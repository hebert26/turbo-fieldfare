Decision: a fixed four-lane receipt-entry validator is admissible for one normal decode produce operation under the boundary below. Extra descriptor use changes resource-failure behavior, not source authenticity. No new user policy decision is required. This is permission to stage a narrowly reviewed candidate, not production acceptance or a run result. Rejected prefetch stays closed.

Descriptor pressure: permit at most FOUR transient entry descriptors per validation, each lane owning at most one from successful openat until deferred close. Root/name-list helper descriptors must be closed before lane dispatch; both retained directory descriptors and already-admitted tensor descriptors remain separately owned as today. Drain all lanes and close every opened entry before returning or starting root-after/binding/scan two. Preserve O_RDONLY|O_NONBLOCK|O_NOFOLLOW|O_CLOEXEC, the original fstat/fstatat sequence and comparisons. Do not duplicate entry opens, leave speculative opens queued after settlement, or retry serially after any failure.

The extra at-most-three simultaneous entry descriptors can turn an otherwise successful serial scan into an open failure under EMFILE/ENFILE. That fails closed through the existing unavailable-file error and must remain a real failed operation. The current contract does not promise successful validation at the serial path’s minimum FD headroom. No additional free-FD guard is necessary for authenticity; a count or rlimit snapshot cannot reserve capacity against other threads anyway. Do not claim identical availability or errno precedence. Retain deterministic minimum receipt-index selection from actually observed entry errors, including indexed cancellation, only after all workers settle. Keep error mapping unchanged rather than disguising resource failures with fallback success.

Required observation invariant: each successful validation observes every receipt entry afresh in BOTH scans, using the same held/named fingerprints and regular-file/single-link constraints. Preserve receipt sorted-inventory verification, requireRoot then full listing (including current expected.isSubset semantics), each entry’s internal open→held stat→named stat→compare→remember→close order, final requireRoot, intervening validateBinding, second complete scan, and final validateBinding. Neither full-source scan is coalesced, cached or moved across map/submit. Root/binding checks do not overlap a still-running entry lane. No GPU use occurs before the complete original post-map validator returns successfully.

Evidence: OfficialSourceHandle.validateTrustedReceipt (:276 onward) specifies binding the verified receipt to held descriptors and current literal names. Its implementation is a sequence of non-atomic filesystem observations, not a snapshot or an atomic mutation detector. OfficialSourceReceiptBindingTests checks unchanged binding and rejects shard, sidecar and root replacement between verification and handle acquisition. These requirements remain covered by fresh per-entry observations and the unchanged post-map boundary. No receipt-entry callback or test requires ascending wall-clock visitation across different filenames. Existing protected payload checkpoint ordering is a separate contract and must remain untouched.

Parallel visitation does not reproduce the serial timeline. An external transient event timed to a particular visit can change which call fails, and cancellation/resource races can select a different observed error. Even serial executions do not guarantee capture of every arbitrarily brief event between syscalls. Persistent replacement/content/metadata changes remain subject to pinned inode, size, mode, link, mtime/ctime and root/binding rejection. Do not describe this as temporal equivalence or a universal transient-mutation guarantee. The admissible claim is the same fresh complete set of required checks, per-entry sequencing and outer safety boundaries, with no observed failure suppressed. If a future caller exposes an ordered per-entry hook, this parallel path is ineligible for that caller.

Precise integration: default-off exact1 gate; only the trusted-receipt branch reached from a normal decode produce with an explicitly owned cancellation latch. Each lane processes ascending indices, checks the latch before every fresh open, stops its own range at its first failure/cancellation, and records that indexed outcome. Other lanes drain their already-owned work; select the minimum indexed error before root-after. No unsafe task handle, new await before GPU commit, model-global mutable latch or arbitrary hook on workers.

Prefill, turn admission, sampler, non-receipt fallback and calls without this proven operation lifetime remain serial. Default-off follows the existing serial implementation. Retain genuine no-hook eligibility for the first isolated comparison and the same actual LFU/routing/math; no prefetch runs alongside it. Four lanes may increase CPU cost even if decode wall improves. The prior standalone evidence justifies this staged boundary, not a 20-tokens/second claim.
