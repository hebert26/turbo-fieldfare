`-Q` does not change the percentage. In Apple `system_cmds` `memory_pressure/memory_pressure.c` at `e0c267e80e451b9441ec4f4bb05dd72f0b49d596`, `-Q` sets `quiet_mode_on`, which skips `print_vm_statistics`. `get_percent_free` calls `memorystatus_get_level`. The quiet print is `System-wide memory free percentage`. In xnu `xnu-10002.1.13` `osfmk/vm/vm_pageout.c`, `vm_pressure_response` on `XNU_TARGET_OS_OSX` sets `available_memory` to `AVAILABLE_NON_COMPRESSED_MEMORY` and `memorystatus_level` to `(available_memory * 100) / atop_64(max_mem)`. `osfmk/vm/vm_compressor.h` defines that macro as `vm_page_active_count + vm_page_inactive_count + vm_page_free_count + vm_page_speculative_count`. Wired pages, compressor-pool pages, and stolen pages are outside it. File-backed cache in inactive or speculative stays inside it. The non-macOS branch of the same function uses jetsam `memorystatus_available_pages` (file-backed + free + secluded-over-target + purgeable). The installed kernel was not disassembled. A newer kernel that moved this assignment would show up in the `vm_stat` sample below.

A drop in this counter is pages leaving that four-way sum. Filling the file cache does not by itself lower it.
